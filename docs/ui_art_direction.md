# NovelAgent UI 美术设计方向

> 本文档补充 [`frontend_design_system.md`](frontend_design_system.md)：设计系统规定“组件与令牌怎么做”，本文规定“画面应该长什么样、为什么这样长”。后续前端改动必须同时对照两份文档。

## 1. 产品气质

NovelAgent 的前端不是后台管理系统，也不是纯代码编辑器，而是一个**商业级创作引擎 / 叙事游戏工作台**。

关键词：
- **玩家视角优先**：用户首先是“创作者/玩家”，不是“系统维护者”。
- **沉浸但克制**：接近游戏 UI 的氛围、反馈与动效，但不堆砌装饰，不牺牲信息密度。
- **内容为王**：正文、角色、RP 对话、状态、设定永远是视觉焦点；工具栏与配置必须退居二线。
- **专家能力后置**：YAML、文件名、底层 job kind、runner、pipeline 等技术细节默认隐藏；必要时放进“专家模式 / 调试模式”。

## 2. 视觉母题

### 2.1 主工作台
- 基础风格：暗色优先，低饱和表面，蓝紫色作为主交互色。
- 空间组织：顶栏负责全局项目与快速入口；左侧 rail 是“模式切换”；中间是多标签画布。
- 形态语言：圆角卡片、柔和描边、轻阴影、低幅度 hover 位移。
- 禁止：大面积硬黑、硬白、纯技术表格堆叠、没有层级的文本墙。

### 2.2 RP 模式
RP 是最接近“游戏”的区域，应明显区别于普通表单页。

- 玩家气泡：右侧、主色渐变、短而明确。
- GM 旁白：左侧、低饱和背景、可轻微 italic，像旁白文本框。
- 角色反馈：左侧、角色色描边/头像，保留舞台感。
- 掷骰 / 技能：居中徽章，像游戏判定结果；颜色使用 `--warning`。
- 输入框：纯自然语言提示，不出现 `target:` / DSL / YAML 之类命令。

### 2.3 设置 / 创作 / 素材
这些区域必须把“底层技术文件”包装成用户能理解的概念。

| 原始概念 | UI 展示 |
|---|---|
| config/server.yaml | 启动与访问 |
| config/models.yaml | 模型通道 |
| config/agents.yaml | 角色与技能 |
| config/pipeline*.yaml | 创作流程 |
| 文件树 | 素材库 / 设定集 / 当前状态 / 大纲 |
| run-scene | 写下一场 |
| rp-turn | 推进 RP |
| import | 导入素材 |

专家仍可展开底层内容，但默认 UI 不应直接暴露文件名。

## 3. 交互原则

1. **每个主动作都有下一步反馈**：创建、保存、运行、导入、RP 发送必须有 loading / toast / 状态块。
2. **拖拽只用于可理解的排序**：标签页、设置卡片、未来 prompt 模块挂载；不做“看起来高级但用户不知道后果”的拖拽。
3. **错误是剧情外提示，不是堆栈**：普通用户看到“场景已存在，请换编号或查看归档”；专家模式再显示底层异常。
4. **默认安全**：真实 LLM 调用必须显性标注；mock 是默认验证路径。
5. **动效轻量**：hover 1-2px 位移，视图切换淡入，不做高频炫技动画。

## 4. 页面方向

### 概览
- 目标：回答“当前故事在哪、发生了什么、下一步看哪里”。
- 多折叠栏必须自然高度 + 外层滚动，不能互相挤压。
- 后续可增加“状态摘要卡”和“下一步推荐”。

### 角色卡
- 目标：像游戏角色面板，而不是 JSON dump。
- 正则前端 widget 可保留 HTML 语义，但容器应统一卡片化。

### RP 对话
- 目标：接近文字 RPG / TRPG 跑团界面。
- 用户只输入自然语言；target/intent/dice 由后端解析后以 chip / badge 回显。

### Prompt / 专家编辑
- 目标：高级用户可编辑，但普通用户不需要进入。
- 后续应命名为“创作指令”，并按写作/审查/归档分类。

### 设置
- 目标：卡片化表单 + 专家模式。
- 默认展示“启动与访问 / 模型通道 / 角色与技能 / 创作流程 / 运行策略 / 记忆召回”。
- YAML 仅在专家模式中出现。

### 素材库
- 目标：让文件页变成“项目资料库”。
- 按设定集、状态、大纲、创作指令、模块、前端组件、导入数据分区。

### 创作
- 目标：把 run job 包装成创作任务。
- 三个主动作：写下一场、推进 RP、导入素材。
- 底层 job kind 只在专家信息里显示。

## 5. 验收底线

一次用户测试至少要能自然完成：
1. 双击启动并自动进浏览器；
2. 新建项目；
3. 在素材库查看/编辑设定；
4. 在创作页跑一次 mock；
5. 在 RP 页用自然语言推进一回合；
6. 在设置页不用看 YAML 就能改启动端口/自动打开浏览器；
7. 遇到错误时知道下一步怎么做。
